# 公开发布清单

这份清单适用于把模板、个人简历或其衍生仓库发布到 GitHub、Overleaf Gallery、个人网站或招聘平台。自动扫描通过不等于可以公开；对每个方框都应进行人工确认。

## 1. 内容

- [ ] 姓名、头像、签名、手机号、邮箱、住址、证件号均为预期公开的信息或虚构示例；公开模板的手机号使用 `X` 等不可拨打占位符，不假设某个全数字号码无人使用。
- [ ] 学校、公司、团队、客户、导师、同事和推荐人信息可公开。
- [ ] 项目名、域名、仓库地址、工单号、内部系统名与截图已移除或泛化；示例链接只使用 `example.com`、`example.net` 或 `example.org` 保留域。
- [ ] 指标、营收、成本、流量、故障、模型数据与路线图不受保密协议或组织政策限制。
- [ ] 链接逐个打开检查，确认没有访问 token、分享密钥、跟踪参数或私有文档权限。
- [ ] 注释、隐藏文本、LaTeX 宏、备用段落和未渲染内容也已检查。

## 2. 文件与元数据

- [ ] 只提交源文件；本地 PDF、日志、辅助文件、编辑器缓存和系统文件未进入 Git。
- [ ] 必须发布的图片已清除 EXIF / GPS / 作者信息并确认版权。
- [ ] 必须发布的 PDF 已检查 Author、Creator、Title、Subject、Keywords、XMP、附件和创建时间。
- [ ] 文件名、目录名、符号链接和文本中没有本机用户名或绝对路径。
- [ ] 字体与第三方素材允许再分发，并附带所需许可证。
- [ ] 压缩包与 Office 文件已作为容器展开检查，而不是只看扩展名。

可用以下命令检查一个候选 PDF；显式文件参数会检查元数据，即使该文件被 `.gitignore` 忽略：

```bash
python3 scripts/privacy_check.py /path/to/candidate.pdf
pdfinfo /path/to/candidate.pdf
```

## 3. Git 历史

- [ ] `make privacy-history` 通过。
- [ ] `git log` 中的 author 与 committer 姓名、邮箱符合公开预期。
- [ ] 已删除文件、旧版本、merge commit、tag、stash 和 LFS 对象不含私人内容。
- [ ] 分支名、tag 名和 commit message 不含内部编号或个人信息。
- [ ] 公开远端来自干净历史；没有把私人仓库完整镜像推送出去。
- [ ] 如果秘密曾被提交，已经先轮换秘密，再重写所有相关引用；只重写历史不能撤销泄露。

对于从私人简历派生的模板，最稳妥的方式是把审核后的最终文件复制到新目录，创建新的根提交。若必须保留部分历史，应使用专门的历史重写工具，并让另一位审阅者复核所有可达对象。

## 4. 平台表面

- [ ] GitHub 仓库简介、Topics、默认分支、Actions、Packages、Releases 和 Pages 已检查。
- [ ] Issue、PR、Discussion、review comment、CI 日志和 artifact 中没有敏感内容。
- [ ] GitHub 提交邮箱隐私设置已开启，或明确接受展示当前公开邮箱。
- [ ] Overleaf 项目没有开启不必要的公开分享，协作者与链接权限正确。
- [ ] 个人网站、简历下载链接和 CDN 缓存中的旧版本已经处理。
- [ ] 用未登录的浏览器访问最终页面，确认外部访客实际能看到的内容。

## 5. 自动验证

```bash
make ci
```

该命令运行扫描器回归测试、当前文件与可达历史隐私检查，并编译所有内置主题、确认每份 PDF 只有一页。发布后仍应定期复查依赖、GitHub Actions 与下载文件。
